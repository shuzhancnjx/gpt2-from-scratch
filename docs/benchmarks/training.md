## What we evaluate, and why

A language model is a machine for assigning probabilities to text. So the most direct
measure of how good it is: **how much probability does it give to real text it has never
seen?** Everything below is a version of that question.

### 1 · Validation loss — average surprise on unseen text

For every token in held-out text, the model gives a probability *p* to the token that
actually came next. Its **surprise** is −log *p*: near 0 if it was confident and right,
large if it gave the real token little probability. Validation loss is the average
surprise over many tokens — the same quantity as the training loss, measured on text the
model never trained on.

| unit | formula | reading |
|---|---|---|
| **nats/token** (the loss) | mean of −ln *p* | the raw number; lower is better |
| **perplexity** | e^loss | "as uncertain as choosing uniformly among this many tokens" |
| **bits/token** | loss ÷ ln 2 | bits needed to encode each token using the model — the compression view |

Anchors: a model that knows nothing (uniform over 50,257 tokens) scores ln 50,257 ≈
**10.8** (perplexity 50,257). The old checkpoint scores **4.17** (perplexity ≈ 65).

**Why held out:** training loss can fall by memorising; validation loss only falls if
the model generalises. (With a single pass over fresh data, the two should stay close —
a widening gap would mean something is wrong.)

**Why a fixed window:** every model is scored on the same first 1,048,576 tokens of the
val shard, so a difference between two numbers is a difference between the models.

**What it cannot tell you:** whether the probabilities mean anything — a model can get
good at grammar and common phrases without "understanding". And it is only comparable
between models that share a tokenizer and are scored on the same kind of text.

### 2 · Loss by position — does the model use its context?

The same loss, broken down by where the token sits in its 1,024-token window. At
position 0 the model has no context and must guess from token frequencies alone; by
position 1,023 it has seen 1,023 tokens. **The drop from early to late positions measures
how much the model gains from context.** A better-trained model should push the late
positions lower while the earliest barely move — context use, not vocabulary, improves.

### 3 · HellaSwag — does higher likelihood track meaning?

10,042 multiple-choice questions: a context and four endings, one real, three fluent but
wrong (generated by a model, then filtered to fool models). The model answers by
**likelihood alone** — the ending it finds most probable after the context wins. No
fine-tuning, no instructions: it tests whether the probabilities the model learned carry
commonsense meaning, on text unlike its training data.

| score | how | why |
|---|---|---|
| `acc` | ending with the highest **total** log-probability | penalises long endings for having more tokens |
| **`acc_norm`** | highest **mean** log-probability per token | the standard figure; removes the length bias |

Anchors: random guessing **25%**; OpenAI's GPT-2 124M roughly **29–30%** `acc_norm`.
Small models sit close to chance for a long time, then climb — the questions need
world knowledge, which arrives later in training than grammar does.

### 4 · MFU — not quality, but cost

Model FLOPs utilisation: the FLOPs the model *needs* per second (≈ 6 × parameters per
token for forward + backward, plus attention) divided by the GPU's peak. It says how well
the run used the hardware — the roofline (P1.1) applied to training.

### 5 · Samples — the sanity check

Fixed prompts at every checkpoint, and the chat UI before and after. Not a metric, but
the check that the numbers mean what you think: a falling loss with garbled samples
would point to a bug in the evaluation, not progress.

### Reading them together

| what you see | what it suggests |
|---|---|
| loss falls, HellaSwag flat near 25% | learning surface statistics (grammar, frequent phrases), not yet meaning — normal early on |
| HellaSwag rises while loss flattens | gains in the hard, rare predictions that average loss barely registers |
| val loss pulls away above train loss | memorisation — should not happen in one pass over fresh data; check for repeated data |
| sudden val-loss spikes | optimisation instability: learning rate, warm-up, or a bad batch |
| late-position loss improves, position 0 does not | the model is learning to use context — exactly what longer training should buy |
